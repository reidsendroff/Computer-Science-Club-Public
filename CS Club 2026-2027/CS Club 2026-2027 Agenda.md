## Purpose and lesson learned

The club exists to help students become confident programmers through making, debugging, explaining, and improving real code together. No experience is required.

In 2025–2026, attendance fell from about 15 members to roughly 3–4 after lessons moved into binary search, BFS, and DFS before most members had the necessary programming foundation. In 2026–2027, the first ten member meetings are one shared Java foundation. There is no early lane split. Algorithms follow the [readiness gates](curriculum/READINESS_GATES.md), not the calendar alone.

## Program promises

- Every meeting ends with visible, runnable code.
- Direct instruction lasts no more than 8–10 minutes at a time.
- At least half of every meeting is hands-on.
- Each activity offers core, support, and stretch choices without public labels.
- Anonymous pace/fun checks and recovery sessions shape the next meeting.
- Experienced members receive meaningful extensions and mentoring opportunities without forcing beginners to skip prerequisites.

## Success outcomes

By year end, members should be able to write, read, run, and debug Java; decompose problems into methods; work with arrays, strings, objects, and collections; explain simple algorithm choices; and contribute to a team project or appropriately leveled challenge.

Program health is measured using aggregate retention from the first stable three-meeting cohort, completion of runnable builds, anonymous pace/fun signals, recovery success, and member-led contributions. Metrics improve the program; they never rank students.

## Weekly meeting standard (60 minutes)

- 0:00–0:05 — welcome, visible goal, and quick hook
- 0:05–0:13 — explanation/live demo (8 minutes)
- 0:13–0:38 — guided core build with optional support
- 0:38–0:50 — choice time: finish, remix, or stretch
- 0:50–0:56 — member demos and debugging discussion
- 0:56–1:00 — run the final code, exit ticket, anonymous pace/fun check

If setup fails, use the verified browser-based or paired-device fallback in [Java Setup](curriculum/JAVA_SETUP.md); setup must not consume the meeting.

## September–November roadmap: shared Java common core

Subject to the verified school calendar, Java foundations dominate September through November. The first ten member meetings follow this sequence even if cancellations shift the calendar. The detailed plan is in [Scope and Sequence](curriculum/SCOPE_AND_SEQUENCE.md).

1. Run, edit, `main`, and `System.out.println` through a small club-introduction program
2. Variables, primitive types, `String`, input, and the `Scanner` newline gotcha
3. Boolean expressions and conditionals
4. Loops and repeated behavior
5. Methods, parameters, return values, and scope
6. Arrays, strings, indexing, and traversal
7. Debugging, small tests, and reading stack traces
8. Classes, objects, constructors, private fields, and public methods
9. `ArrayList` and a team mini-capstone
10. Algorithm bridge: linear search, minimum/maximum, counting, and complexity intuition

`public static void main(String[] args)` is provided as a scaffold in early weeks. Its component syntax is revisited explicitly when methods, access modifiers, static members, arrays, and parameters have been taught.

### Fall reset rule

At a checkpoint, progression requires attendance of at least 60% of the privately defined active cohort and completion of every core evidence item by at least 80% of checkpoint participants who receive 20 or more hands-on minutes. If attendance is invalid, readiness is below 80%, or at least 30% of valid anonymous pace responses select “too fast,” the next shared meeting repeats or opens with recovery. Use the full absence, pair-work, response-coverage, and two-attended-meeting recheck rules in [Readiness Gates](curriculum/READINESS_GATES.md). The group does not advance merely to match a calendar.

## Post-foundation roadmap: mastery-gated algorithms and projects

The complete meeting-by-meeting plan for this portion of the year is in the [DSA-Incorporated Agenda](DSA-incorporated%20Agenda.md).

### Weeks 11–12 — binary search, only after the Java Foundations Gate

- Review sorted data, indexes, loops, conditionals, method contracts, and linear search.
- Trace the search interval before coding.
- Compare linear and binary search using small measured examples.
- Every member stays in the shared meeting. Support variants revisit the prerequisite inside the same objective, with an equivalent recheck and reintegration within two attended meetings.

### Next phase — collections and problem-solving tools

- Sorting and comparison
- Stack and queue behavior
- `HashSet` and `HashMap`
- Two-pointer and counting patterns where prerequisites are met
- Team project planning, small releases, code review, and testing

### Later phase — recursion and graphs, only after the Graph Traversal Gate

- Recursion or an equivalent explicit-state model
- Graph vocabulary and adjacency-list representation
- Traversal invariants and visited state
- BFS with a queue, then DFS with recursion or a stack
- Shortest paths only after weighted graphs and priority queues

Dynamic programming and advanced graph topics are optional late-year extensions, never calendar obligations. See [Algorithms](curriculum/algorithms/README.md) for all prerequisite chains.
