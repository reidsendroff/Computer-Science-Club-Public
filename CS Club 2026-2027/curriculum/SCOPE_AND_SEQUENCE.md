# Scope and Sequence

All ten opening meetings are shared Java foundations. Each 60-minute meeting uses short instruction, at least 30 minutes of coding, core/support/stretch choices, visible runnable output, and an exit ticket.

| Week | Focus | Runnable build and evidence | Support | Stretch |
| --- | --- | --- | --- | --- |
| 1 | Run/edit, `main`, and `println` | Create, personalize, and run a small club-introduction program twice | Facilitator steps, pair run, browser fallback | Multi-line interactive story; explain each edit |
| 2 | Variables, primitive types, `String`, `Scanner` | Input a name/value and print a computed response | Input template and type table | Validate input; investigate `nextInt()`/`nextLine()` newline behavior |
| 3 | Booleans and conditionals | Build a choice-based recommendation or eligibility checker | Condition frames and truth-table cards | Compound conditions and boundary tests |
| 4 | Loops | Build a counter, pattern, or repeatable game turn | Trace table and partially completed loop | Nested loop pattern or input-controlled loop |
| 5 | Methods, parameters, returns, scope | Refactor repeated behavior into two tested methods | Method signature template and call diagram | Overload a method; contrast local/parameter/static scope |
| 6 | Arrays, strings, indexing, traversal | Analyze a small list or message | Index diagram and guided loop | Multiple passes or character-frequency count |
| 7 | Debugging, tests, stack traces | Repair seeded bugs and add boundary checks | Error-reading checklist and paired debugging | Write a tiny test harness and classify failures |
| 8 | Classes, objects, constructors, private fields, public methods | Model an object whose public behavior changes private state | Class skeleton and object diagram | Add validation and a `static final` constant |
| 9 | `ArrayList` and team mini-capstone | Build a shared tracker/game/catalog with add/view/update behavior | Feature cards and starter class | Search/filter, tests, or design review |
| 10 | Algorithm bridge: linear search, min/max, counting, complexity intuition | Implement and compare simple traversal algorithms | Trace examples and method shells | Count operations across input sizes and justify a choice |

`public static void main(String[] args)` is initially supplied as a runnable entry-point scaffold. Week 5 explains `public`, `static`, `void`, parameters, and returns at an age-appropriate level; Week 6 connects `String[] args` to arrays; Week 8 revisits access and static members.

## Reset triggers

Pause or reteach when any condition is met, using the checkpoint denominator and evidence rules in [Readiness Gates](READINESS_GATES.md):

- fewer than 60% of the privately defined active cohort attend the checkpoint for at least 20 hands-on minutes;
- fewer than 80% of checkpoint participants produce every required core evidence item; or
- 30% or more of valid anonymous pace responses select “too fast,” response coverage is insufficient for a gate decision, or comments reveal a shared prerequisite gap.

Use a shared recovery build, paired trace, or equivalent recheck within two attended meetings; record only aggregate results. Do not create a permanent recovery lane.

## After Week 10

- Weeks 11–12: binary search only after the Java Foundations Gate.
- Following meetings: sorting/comparison, stack/queue, map/set, project iterations.
- Later: recursion or explicit iterative state, graph representation, and the Graph Traversal Gate.
- Only then: BFS/DFS; weighted shortest paths and dynamic programming are optional late extensions after their own prerequisites.
