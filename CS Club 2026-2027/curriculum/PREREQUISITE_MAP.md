# Prerequisite Map

An arrow means “learn and demonstrate the left side before the right side.”

```text
run/edit/print
  -> variables + input
  -> booleans + conditionals
  -> loops
  -> methods + parameters + returns + scope
  -> arrays + strings + traversal
  -> debugging + small tests
  -> classes + objects + encapsulation
  -> ArrayList + team mini-capstone
  -> linear search + min/max + counting + complexity intuition
  -> Java Foundations Gate
  -> binary search
  -> sorting/comparison + stack/queue + map/set
  -> recursion or explicit iterative state
  -> graph representation + visited-state invariant
  -> Graph Traversal Gate
  -> BFS + DFS
  -> weighted graphs + priority queue
  -> shortest paths
```

## Topic requirements

| Topic | Required prior evidence |
| --- | --- |
| Linear search | arrays, indexing, loops, conditionals, methods |
| Binary search | Java Foundations Gate, sorted arrays, linear search, interval tracing |
| Sorting | arrays/ArrayList, comparisons, methods, loop invariants |
| Stack/queue | classes/objects, ArrayList, state changes, method contracts |
| Map/set | objects, equality concept, loops, collections |
| Two pointers | arrays/ArrayList, indexing, loops, conditionals, sorted-data reasoning where required |
| Recursion | methods, parameters/returns, conditionals, call-stack tracing, base case |
| Graph representation | ArrayList, map/set, object references, graph vocabulary |
| BFS | graph representation, queue behavior, visited set, traversal invariant |
| DFS | graph representation, stack or recursion, visited set, traversal invariant |
| Dijkstra | graph representation, BFS contrast, weighted edges, priority queue, nonnegative weights |
| Dynamic programming | recursion or staged state, arrays/maps, subproblem definition, base cases |

If evidence is missing, use the relevant recovery task in [Readiness Gates](READINESS_GATES.md); do not skip prerequisites to match a date.
