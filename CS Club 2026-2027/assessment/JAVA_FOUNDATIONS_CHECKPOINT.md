# Java Foundations Checkpoint

Use at the end of Week 10 as the primary evidence for the [Java Foundations Gate](../curriculum/READINESS_GATES.md#java-foundations-gate-after-week-10). This is a low-pressure build, not a public contest. Apply the gate's privately defined active cohort, 60% attendance-validity safeguard, checkpoint-participant denominator, five-item member checklist, pair-work rule, 80% group threshold, and two-attended-meeting individual recheck window.

## Core task

Build a small Java program that stores several values, calls at least one method with a parameter and return value, traverses the collection with a loop, and reports a search/count/minimum/maximum result. Include one test case and explain one debugging choice.

## Choices

- Support: starter class, method shells, trace table, and sample data
- Core: implement the required behavior and show two runs
- Stretch: use an object or `ArrayList`, validate input, add tests, or compare operation counts

## Evidence rubric

- Code runs and the member can explain the output.
- Conditionals/loops and indexing are used safely.
- Method input/output is understood.
- Variable kinds are described accurately in the program's context.
- A common error can be interpreted and addressed.
- The traversal algorithm is explained in plain language.

Keep recovery inside the shared meeting: use the starter, method shells, trace table, paired roles, or a smaller equivalent input toward the same objective. Provide an equivalent individual recheck within the member's next two attended meetings, then remove scaffolds as soon as the checklist is complete. Do not create a separate or permanent track. Store only aggregate totals in the public dashboard.
