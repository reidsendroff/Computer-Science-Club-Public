# Program Charter

## Mission

Create a place where a student can arrive with no programming experience, make something run in the first meeting, and grow toward collaborative projects and algorithmic problem solving.

## Design principles

1. **Belonging before sorting:** one shared ten-meeting Java foundation; no public levels.
2. **Make before lecture:** short explanations and at least 50% hands-on time.
3. **Visible progress:** every meeting ends with runnable code.
4. **Choice without labels:** core, support, and stretch paths can change each task.
5. **Mastery before complexity:** readiness evidence controls progression.
6. **Recovery is normal:** reteach, partner practice, and private rechecks are built in.
7. **Advanced members still grow:** extensions, code review, testing, design constraints, and mentoring.
8. **Privacy by design:** only aggregate program signals belong in public.

## What members can expect

- Friendly setup help and a zero-install fallback
- Small collaborative builds, debugging, and demonstrations
- A clear route from Java foundations to algorithms and projects
- Optional competition preparation after prerequisites
- Feedback about the lesson, not public judgment of the learner

## What success means

Success is sustained participation and increasing independence: members can explain and modify code, recover from errors, choose an appropriate strategy, and help a teammate. A contest score is one optional signal, not the club's purpose.
